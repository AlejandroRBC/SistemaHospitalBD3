========================================================================
 CONEXION CBBA (SQL Server) -> LPZ (PostgreSQL)
 SISTEMA HOSPITALARIO DISTRIBUIDO
========================================================================

CBBA tiene dos formas de conectarse con LPZ:

  A) Flask HTTP  ->  COMUNICACION POR API  (ya implementada en codigo)
  B) ODBC 16     ->  CONEXION DIRECTA A BD  (Linked Server en SSMS)


========================================================================
 OPCION A: COMUNICACION VIA FLASK HTTP (YA IMPLEMENTADA)
========================================================================

CBBA se comunica con LPZ a traves de su API REST en Flask.

  CBBA (Flask)  -- HTTP -->  LPZ (Flask)  -- SQL -->  PostgreSQL
  lpz_service.py             app.py + routes            hospital_lpz

PASOS:

  1. Verificar que ambas maquinas tengan RadminVPN activo.
     LPZ: 26.10.1.5
     CBBA: 26.10.1.6

  2. En LPZ, iniciar el servidor Flask:
     cd LPZ
     pip install -r requirements.txt
     python app.py
     # Escucha en http://0.0.0.0:5000

  3. En CBBA, confirmar que hospital_ips.py apunte a la IP correcta:
     HOSPITALS = {
         "LPZ": "http://26.10.1.5:5000",
         "CBBA": "http://26.10.1.6:5000",
         "STCZ": "http://26.10.1.7:5000"
     }

  4. Iniciar CBBA:
     cd CBBA
     pip install -r requirements.txt
     python app.py

  5. Probar la conexion:
     - En CBBA, visitar: http://localhost:5000
     - El card "Estado de Conexiones" debe mostrar LPZ en verde "CONECTADO"
     - O manualmente: curl http://localhost:5000/check_conexiones

  6. Probar consulta nacional desde CBBA:
     curl http://localhost:5000/buscar_nacional/1
     # Si el paciente 1 esta en LPZ, LPZ responde via HTTP.
     # Si esta en CBBA local, devuelve el paciente local.

FLUJO COMPLETO DE UNA CONSULTA NACIONAL:

  1. CBBA recibe: GET /buscar_nacional/5
  2. routes/consultas.py llama a lpz_service.buscar_paciente_nacional(5)
  3. lpz_service.py hace: requests.get("http://26.10.1.5:5000/buscar_paciente/5")
  4. LPZ recibe en routes/mediador.py -> mediator.resolve_patient(5)
  5. mediator.py revisa fragment_catalog:
     - Si paciente pertenece a LPZ -> busca en PostgreSQL local
     - Si pertenece a CBBA -> devuelve error (CBBA debio buscarlo local)
     - Si pertenece a STCZ -> requests.get("http://26.10.1.7:5000/paciente/5")
  6. LPZ devuelve JSON unificado a CBBA


========================================================================
 OPCION B: LINKED SERVER VIA ODBC (PSQLODBC 16)
========================================================================

Configurar SQL Server Management Studio (SSMS) en CBBA para que pueda
consultar directamente la base de datos PostgreSQL de LPZ mediante un
Linked Server, usando psqlODBC 16.

Requisito: CBBA ya tiene instalado psqlodbc_16 (PostgreSQL ODBC Driver).
Si no, descargar de: https://www.postgresql.org/ftp/odbc/versions/msi/

PASO 1: CONFIGURAR ODBC DSN EN CBBA (Windows)

  1. Abrir "ODBC Data Sources" (Administrador de origenes de datos ODBC):
     - Windows + R -> escriba "odbcad32.exe" -> Enter
     - Importante: usar ODBC de 64 bits si SQL Server es 64 bits

  2. Ir a la pestana "DSN de Sistema" -> Agregar...

  3. Seleccionar "PostgreSQL Unicode(x64)" -> Finalizar

  4. Completar los campos:
     - Data Source:        LPZ_PostgreSQL
     - Database:           hospital_lpz
     - Server:             26.10.1.5
     - Port:               5432
     - User Name:          postgres
     - Password:           admin
     - SSL Mode:           disable

  5. Hacer clic en "Test" -> debe mostrar "Connection Successful"

  6. Aceptar para guardar el DSN.

PASO 2: CONFIGURAR LINKED SERVER EN SSMS

  1. Abrir SQL Server Management Studio (SSMS) en CBBA.

  2. Conectarse al motor SQL Server local:
     - Server: localhost
     - Authentication: SQL Server Authentication
     - Login: sa
     - Password: 1234

  3. En el Object Explorer, expandir:
     Server Objects -> Linked Servers

  4. Click derecho en "Linked Servers" -> "New Linked Server..."

  5. Configurar la pestana "General":
     - Linked server:        LPZ_POSTGRES
     - Server type:          Other data source
     - Provider:             "Microsoft OLE DB Provider for ODBC Drivers"
     - Product name:         PostgreSQL
     - Data source:          LPZ_PostgreSQL
       (debe coincidir con el nombre del DSN del Paso 1)
     - Provider string:      (dejar vacio)

  6. Ir a la pestana "Security":
     - Seleccionar: "Be made using this security context"
     - Remote login:  postgres
     - With password: admin
     - (la contraseña del usuario postgres en LPZ)

  7. Aceptar para crear el Linked Server.

PASO 3: PROBAR EL LINKED SERVER

  En SSMS, abrir una nueva consulta (New Query):

  -- Probar que la conexion funciona:
  SELECT * FROM OPENQUERY(LPZ_POSTGRES, 'SELECT 1 AS prueba');

  -- Listar tablas en PostgreSQL:
  SELECT * FROM OPENQUERY(LPZ_POSTGRES, '
      SELECT table_name, table_schema
      FROM information_schema.tables
      WHERE table_schema = ''public''
  ');

  -- Consultar pacientes desde LPZ:
  SELECT * FROM OPENQUERY(LPZ_POSTGRES, '
      SELECT id_paciente, nombre, tipo_sangre, alergias,
             enfermedades_cronicas
      FROM paciente
      ORDER BY id_paciente
  ');

  -- Consultar historial clinico de LPZ:
  SELECT * FROM OPENQUERY(LPZ_POSTGRES, '
      SELECT h.id_historial, h.id_paciente, p.nombre,
             h.observaciones, h.fecha
      FROM historial_clinico h
      JOIN paciente p ON p.id_paciente = h.id_paciente
      ORDER BY h.fecha DESC
  ');

PASO 4: USAR EL LINKED SERVER DESDE CODIGO (OPCIONAL)

  Si alguna vez se necesita consultar PostgreSQL directamente desde
  el codigo Flask de CBBA (via pyodbc), se puede usar OPENQUERY:

  from db import get_connection

  def query_lpz_via_linked_server():
      conn = get_connection()
      cur = conn.cursor()
      cur.execute("""
          SELECT * FROM OPENQUERY(LPZ_POSTGRES, '
              SELECT id_paciente, nombre, tipo_sangre

          ')
      """, (patient_id,))
      return cur.fetchall()

  NOTA: No es recomendable para operaciones frecuentes.
  Usar la API Flask HTTP (Opcion A) para el funcionamiento normal.


========================================================================
 COMPARACION: FLASK HTTP vs LINKED SERVER
========================================================================

+---------------------------+---------------------+---------------------+
| Aspecto                  | Flask HTTP (A)      | Linked Server (B)   |
+---------------------------+---------------------+---------------------+
| Tipo de comunicacion     | API REST            | ODBC directo a BD   |
| Latencia                 | Media (2 saltos)    | Baja (1 salto)      |
| Acoplamiento             | Bajo (solo HTTP)    | Alto (driver ODBC)  |
| Seguridad                | Control por Flask   | Credenciales BD     |
| Uso principal            | Consultas nacionales| Administracion/ETL  |
| Dependencia de red       | RadminVPN           | RadminVPN           |
| Implementado             | SI                  | NO (configurar)     |
+---------------------------+---------------------+---------------------+

RECOMENDACION:
  Usar Opcion A (Flask HTTP) para el funcionamiento normal del sistema.
  Usar Opcion B (Linked Server) solo para administracion, reportes o
  migracion de datos entre nodos.


========================================================================
 SOLUCION DE PROBLEMAS
========================================================================

PROBLEMA: El check de conexiones muestra LPZ en rojo.
  -> Verificar que LPZ tenga python app.py corriendo
  -> Hacer ping 26.10.1.5 desde CBBA
  -> Probar en navegador CBBA: http://26.10.1.5:5000/estado

PROBLEMA: ODBC test falla.
  -> Verificar que PostgreSQL en LPZ acepte conexiones remotas:
     En LPZ, revisar postgresql.conf:
       listen_addresses = '*'
     Revisar pg_hba.conf:
       host    all    all    26.10.1.0/24    md5
  -> Verificar puerto 5432 abierto en firewall de LPZ
  -> Probar desde CBBA: psql -h 26.10.1.5 -U postgres -d hospital_lpz

PROBLEMA: Linked Server da error "could not find driver".
  -> Verificar que psqlodbc_16 este instalado en CBBA
  -> Verificar que el DSN de sistema LPZ_PostgreSQL exista en odbcad32.exe
  -> Probar DSN con el boton "Test" antes de crear el Linked Server

PROBLEMA: OPENQUERY devuelve "Column name not found".
  -> Encerrar la consulta SQL entre comillas simples
  -> Escapar comillas simples internas duplicandolas: '' → ''
  -> Ejemplo:
     SELECT * FROM OPENQUERY(LPZ_POSTGRES, '
         SELECT nombre FROM paciente
         WHERE alergias = ''Penicilina''
     ')

PROBLEMA: Timeout en OPENQUERY.
  -> El timeout por defecto es 10 segundos. Para consultas pesadas:
  -> Ir a Linked Server Properties -> Server Options
  -> Aumentar "Query Timeout" (ej: 0 = sin limite)


========================================================================
 VERIFICACION FINAL
========================================================================

Despues de configurar todo, en CBBA ejecutar estos comandos:

  -- 1. Verificar Linked Server existe
  SELECT name, product, provider FROM sys.servers
  WHERE is_linked = 1;

  -- 2. Probar ping al Linked Server
  SELECT * FROM OPENQUERY(LPZ_POSTGRES, 'SELECT current_database(), version()');

  -- 3. Contar pacientes remotos
  SELECT * FROM OPENQUERY(LPZ_POSTGRES, 'SELECT COUNT(*) AS total FROM paciente');

  -- 4. Prueba de join local + remoto (unificar datos)
  SELECT
      p.id_paciente,
      p.nombre,
      p.tipo_sangre,
      r.hospital_origen,
      r.alergias
  FROM paciente p
  LEFT JOIN OPENQUERY(LPZ_POSTGRES, '
      SELECT id_paciente, hospital_origen, alergias
      FROM replica_critica
  ') r ON r.id_paciente = p.id_paciente;
